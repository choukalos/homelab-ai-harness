## Observability Strategy

### 1. LiteLLM Usage Logs

**Source:** LiteLLM's built-in prometheus callback + Postgres metadata DB.

| Metric | Description | Dashboard |
|---|---|---|
| `litellm_completion_tokens` | Total output tokens per model/key | Grafana: LiteLLM Usage |
| `litellm_prompt_tokens` | Total input tokens per model/key | Grafana: LiteLLM Usage |
| `litellm_latency` | Request latency by model | Grafana: LiteLLM Performance |
| `litellm_requests_total` | Request count by model/key | Grafana: LiteLLM Traffic |
| `litellm_budget_snapshot` | Remaining budget per key | Grafana: Budget Monitor |

**Per-Key Usage:** Track each API key (`chuck`, `son`, `openwebui`, `siri`, `automation`, `experiment`) separately.

**Action:** Already configured. No changes needed.

---

### 2. Tool-Call Logs

**Source:** New MCP servers + skill runner.

Each MCP server and skill should emit structured logs:

```
{
  "timestamp": "2026-07-03T04:00:00Z",
  "component": "mcp_search",
  "action": "tool_call",
  "tool": "search_web",
  "requester": "chuck",
  "channel": "cli",
  "latency_ms": 1200,
  "result_count": 5,
  "status": "success"
}
```

| Metric | Source | Format |
|---|---|---|
| Tool call count | MCP server logs | JSON structlog |
| Tool call latency | MCP server logs | JSON structlog |
| Tool call errors | MCP server logs | JSON structlog |
| Tool timeout rates | MCP server logs | JSON structlog |

**Implementation:**
- Each MCP server logs to stdout (captured by Docker)
- Skill runner logs to `/home/chuck/homelab/logs/skill_runner/skill_runner.log`
- Victoria Metrics scrapes structured metrics if the service exposes a `/metrics` endpoint

**New endpoints to add (Phase 14, manual):**
- `mcp_search` — `/metrics` (prometheus format)
- `mcp_knowledge` — `/metrics` (prometheus format)
- `skill_runner` — `/metrics` (prometheus format via FastAPI prometheus middleware)

---

### 3. Skill Job Logs

**Source:** Skill runner (`/home/chuck/homelab/logs/skill_runner/`).

| Metric | Description |
|---|---|
| `skill_jobs_total` | Total jobs launched, by skill name |
| `skill_jobs_by_status` | Jobs by status (pending, running, completed, failed, awaiting_approval, cancelled) |
| `skill_job_runtime_seconds` | Job runtime by skill name |
| `skill_job_errors_total` | Failed jobs by skill name |
| `skill_artifacts_total` | Artifacts generated by skill name |

**Implementation:** The skill runner (FastAPI) can expose a `/metrics` endpoint using `prometheus_client`. Victoria Metrics scrapes it.

**Dashboard:** Grafana dashboard "Skill Runner" with per-skill pie charts, runtime histograms, and error rate line charts.

---

### 4. Artifact Logs

**Source:** Skill runner + filesystem monitoring.

| Metric | Description |
|---|---|
| `artifact_count` | Total artifacts per type (research_reports, investment_briefs, presentations, etc.) |
| `artifact_size_bytes` | Total storage consumed per type |
| `artifact_age_days` | Age distribution of artifacts |

**Implementation:** Periodic filesystem scan or skill runner emits on each artifact save.

---

### 5. Token Counts & Context Size

**Source:** LiteLLM prometheus callback (already captured).

| Metric | Description |
|---|---|
| Input tokens per request | Context window consumption |
| Output tokens per request | Response size |
| Context utilization | (input_tokens / max_context) × 100 |
| Token throughput | Tokens/second per model |

**Dashboard:** Grafana "Token Usage" dashboard with per-key and per-model breakdowns.

---

### 6. Latency

**Source:** LiteLLM prometheus callback + MCP server logs + skill runner logs.

| Component | Latency Target | Alert Threshold |
|---|---|---|
| LiteLLM (model response) | < 5s for first token, < 30s total | > 60s |
| MCP search | < 3s | > 10s |
| MCP knowledge | < 2s | > 5s |
| Skill runner (siri_ask) | < 15s total | > 30s |
| Skill runner (deep_research) | < 300s total | > 600s |
| Skill runner (presentation_build) | < 300s total | > 600s |

---

### 7. Tool Error Rates

**Source:** MCP server logs + skill runner logs.

| Metric | Description |
|---|---|
| `tool_errors_total` | Failed tool calls by tool name |
| `tool_error_rate` | Errors / total calls per tool |
| `tool_timeouts_total` | Timeout events by tool |
| `tool_timeout_rate` | Timeouts / total calls per tool |

**Alert:** Error rate > 5% for any tool over 1 hour.

---

### 8. Model Error Rates

**Source:** LiteLLM prometheus callback + Postgres.

| Metric | Description |
|---|---|
| `model_errors_total` | Failed requests by model |
| `model_error_rate` | Errors / total requests per model |
| `model_5xx_count` | 5xx responses by model |
| `model_timeout_count` | Timeout responses by model |

**Alert:** Error rate > 10% for any model over 1 hour.

---

### 9. Public Endpoint Access Logs

**Source:** Caddy access logs + LiteLLM request logs.

| Metric | Description |
|---|---|
| `caddy_requests_total` | Requests per route |
| `caddy_response_codes` | 2xx/3xx/4xx/5xx per route |
| `caddy_latency` | Response time per route |
| `llm_public_requests` | Requests to llm.choukalos.com by key |
| `siri_public_requests` | Requests to siri.choukalos.com |

**Alert:** Unusual traffic spikes (> 3× average) on any public endpoint.
