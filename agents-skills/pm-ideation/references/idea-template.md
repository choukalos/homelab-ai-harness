# Idea template

The body of a board idea created by `pm-ideation`. Written into the idea text
at `add_idea` time (or `edit_idea` in `idea` state).

```markdown
## <Problem statement — verb-led, user-observable, one line>

**Value hypothesis:** if we <action>, then <outcome>, because <reason>.
**Target user:** <who hits this problem — the operator, which agent role,
which site visitor>
**Success metric:** <how we'll know it worked — the one number or observable
that decides>
**Rough size:** S | M | L — <one-line basis>
**Kano class:** must-be | performance | attractive | indifferent
**Evidence:** <the signal — PM-1 opportunity id / BA report / feedback quote,
with source links>
**Not this:** <what this idea explicitly is not — the nearest neighbor it
could be confused with>
```

Field notes:

- **Problem statement (title)** — the user's problem, not the solution.
  "Build a dashboard" fails; "I can't tell which content is driving traffic"
  passes.
- **Value hypothesis** — falsifiable: if it can't be wrong, it's not a
  hypothesis.
- **Success metric** — one, measurable, tied to the org goal where possible.
- **Rough size** — S/M/L, relative effort (R8: time estimates create false
  precision). Detail sizing is PM-2 / DEV-2's job.
- **Kano class** (R8) — must-be = expected (absence disappoints, presence is
  taken for granted); performance = more is better, linear; attractive =
  delighter; indifferent = no effect. Categories drift — today's delighter
  becomes tomorrow's must-be.
- **Not this** — the dedupe guard for the next ideation pass.
