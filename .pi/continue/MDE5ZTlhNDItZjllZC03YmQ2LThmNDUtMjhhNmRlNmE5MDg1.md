## Learned
- Kaleido v1+ requires Chrome browser. Must run kaleido.get_chrome_sync() once in the runtime environment before any fig.to_image() call, otherwise ChromeNotFoundError is raised. — source: python3 test of kaleido at line ~26 of test script raised ChromeNotFoundError, resolved by running kaleido.get_chrome_sync()
- Plotly 6.x update_layout takes **kwargs dict, NOT a go.Layout positional object. Passing go.Layout instance causes layout merge failures. Use fig.update_layout(**dict_of_kwargs). — source: charts/service.py rewrite: original _build_layout returned go.Layout(cfg) which broke when passed to fig.update_layout(); fixed by returning plain dict
- Plotly 6.x Layout uses title_text, title_x, title_xanchor as top-level kwargs rather than nested title dict (title={text:..., x:...} emits deprecation warnings). — source: charts/service.py _layout_kwargs function uses title_text, title_x, title_xanchor, title_font top-level keys
- The edit tool rejects 'path' inside individual edit objects; the path key belongs at the top-level call argument. Repeating 'path' in each edit dict causes 'must not have additional properties' validation errors. — source: Repeated edit validation failures on layout/schemas.py when each edit dict included a 'path' field
- Project pattern: each feature module follows __init__.py, schemas.py (Pydantic), service.py (business logic), router.py (FastAPI). New modules must match this shape for consistency. — source: Observation across layout/, media/, family_kb/, web_search/, siri/, filetools/ modules — all use identical structure
